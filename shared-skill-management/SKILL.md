# 共享技能库管理

在这台 Windows 电脑上，以 `C:\Users\33509\.agents\skills` 为用户级技能的工作目录和唯一发布目录。把技能放在 `<技能名>\SKILL.md`，同包的脚本、参考资料和资源保留相对路径。临时下载和备份放在技能扫描目录之外。

## 必须先调用

只要请求的任一步会改变 Agent 技能的内容、文件、安装状态、启用状态或客户端链接，先调用并应用本技能，再执行变更。即使技能变动是另一个任务的附带步骤，或者没有明确提到本技能，也要触发。更新本技能自身同样适用。

- 安装、创建、更新、替换、重命名、迁移、启用、禁用、卸载和删除技能都属于变更。
- 修改技能说明、触发描述、参考资料、脚本或资源，以及调整同步链接，也属于变更。
- 先用本技能确定作用范围、工作目录和同步路径，再使用具体的安装器或技能编写工具。完成后按下文核对客户端。

## 安装与更新

1. 从共享目录开始检查。确认目标名称、用户指定的来源、版本和操作范围。更新时先查现有内容、链接类型和目标，识别本地修改与同名独立版本。
2. 使用明确的目标目录安装。GitHub 链接指向单个文件时，安装包含该文件的完整技能目录。使用支持自定义目标的安装器时，传入 `--dest "C:\Users\33509\.agents\skills"`。记录实际采用的上游提交或版本。创建技能时，验证目录名与 `SKILL.md` 的 `name` 一致，且含有 `description`。
3. 在共享目录里完成发布。更新时先在临时目录校验新包，再替换目标技能目录。保留用户的本地修改，遇到实质冲突时说明。若技能目录本身是指向供应商的链接，先核对其目标和供应商的更新方式。删除技能时，核对绝对路径和链接类型，只删除用户指定的内容。

## 发现并同步本机 Agent

### Gemini 特殊同步规则

本机 Gemini 本地配置技能目录为 `C:\Users\33509\.gemini\config\skills`。该目录中的共享技能必须使用完整的实体副本，不使用指向共享库的链接；共享库仍是维护源。新增或更新共享技能后，将完整技能包复制到 Gemini 并校验文件，删除共享技能时同步处理 Gemini 对应副本。同步前检查并保留 Gemini 独有技能、配置和本地修改；遇到同名独立内容或修改冲突时先核实，不覆盖未获授权的内容。副本不会自动更新，每次共享技能变更后须显式同步。报告文件系统同步结果时，将客户端实际加载验证单独说明；不要仅凭目录存在推断客户端会扫描它。

其他客户端继续使用指向共享库的链接，并保留系统技能、独立技能和既有配置。

每次使用本技能时，先自动发现本机 Agent 和客户端，不依赖固定名单。读取 Windows 已安装应用（卸载注册表、开始菜单或已安装应用包）、PATH 中可用的 Agent CLI、用户配置目录及现有技能链接。按应用、CLI 和实际扫描路径核对并去重，保留经确认会独立扫描的入口。逐个确认客户端是否支持技能、实际扫描的用户级路径、链接目标及安装状态。仅有名称、残留目录或推测路径时，标记为未验证；可查本机配置或官方文档补证。仅对已核实的入口执行获授权的修改。

- 逐个处理已确认支持技能的客户端：Gemini 按上述特殊规则使用实体副本；其他客户端优先将其个人技能目录整目录联接到共享库；若该客户端不支持或不适合整目录联接，采用经确认可用的方式并说明原因。转换前检查和保留系统技能、独立技能、配置、链接和同名冲突，不覆盖或删除未获授权的内容。
- 新增、更新或删除共享库中的技能后，逐个核查已发现客户端的实际入口、链接目标和变更项是否可读取；若某客户端无法检查或同步，记录原因。避免把不同路径直接认作不同 Agent，先核实其用途。
- 保留项目级、应用内置和市场技能；不要将客户端独有文件随意推广到其他客户端。客户端仍显示旧列表时，检查其缓存或刷新方式；将文件系统验证与客户端内实际加载验证分开报告。

## 每次调用后的报告

每次使用本技能，无论用户手动调用还是任务自动触发，都要在用户可见的最终回复中明确说明「本次已使用 shared-skill-management」。仅检查、无需修改、部分完成或受阻时也要报告。

报告应明确指出相关技能的实际安装目录，以及本机发现的各 Agent 逐一核查后的同步情况（包括未验证或不支持的情况）；说明已核实的链接与可读取状态，区分文件系统检查和客户端实际加载验证。若未检查、存在冲突或同步失败，应如实说明，不推断成功。卸载时说明原安装位置及链接清理状态。
